# Product Requirements Document: Agctor System

## 1. Introduction

**Product Name:** Agctor System  
**Description:** A .NET-based actor model framework for building agentic systems with pluggable backends and extensible agent capabilities.

The Agctor System is designed to provide a robust foundation for developing agentic applications using the actor model pattern. It features a core SDK with swappable runtime backends, a standardized message protocol, and a CLI interface for interacting with agents.

## 2. Current System Capabilities

### 2.1 Core Architecture

#### 2.1.1 Actor Model Implementation
- ✅ **IActor Interface**: Fundamental contract for all actors with lifecycle management, message processing, and state tracking
- ✅ **Message Envelope**: Standardized message wrapper (IMessageEnvelope) with metadata, headers, and routing information
- ✅ **Pluggable Runtime Architecture**: Hot-swappable backend adapters using the IActorRuntimeAdapter interface
- ✅ **InMemory Runtime**: Fully functional in-memory actor runtime for development and testing

#### 2.1.2 Agent System
- ✅ **IAgent Interface**: Extension of IActor that provides agent-specific capabilities
- ✅ **Agent Factory**: Factory for creating and managing agents (IAgentFactory)
- ✅ **Agent Status Tracking**: States include Idle, Working, WaitingForSubtasks, WaitingForHumanInput, Completed, Failed
- ✅ **Agent Hierarchy**: Support for parent-child agent relationships with subtask delegation
- ✅ **Root Agent Architecture**: Primary coordinator agent that receives user requests and orchestrates task completion
- ✅ **Failure Handling**: Standardized approach for handling and reporting agent failures with appropriate error messages

#### 2.1.3 Message Communication Protocol (MCP)
- ✅ **Standardized Envelope**: All agents communicate using the standardized MCP envelope format
- ✅ **Metadata & Headers**: Support for rich metadata and headers for message routing and context
- ✅ **Serialization**: JSON serialization for message payloads (with planned support for other formats)
- ✅ **Hierarchical Communication**: Parent-child message passing with clear responsibility chains

#### 2.1.4 Error Handling and Logging
- ✅ **Centralized Error Handling**: Middleware-based approach for consistent error processing across the system
- ✅ **Error Context**: Standardized error context with source, exception details, and original message
- ✅ **Error Pipeline**: Support for pluggable error handlers in a processing pipeline
- ✅ **Standardized Logging**: Consistent logging interface (IAgctorLogger) with multiple severity levels
- ✅ **Console Logger**: Colorized console output with timestamps and categorization
- ✅ **Logger Factory**: Centralized logger creation and configuration
- ✅ **Dependency Injection**: Full integration with DI container for logging and error handling services

### 2.2 Implemented Features

#### 2.2.1 LLM Integration
- ✅ **LLMAgent**: Agent that communicates with local LLM (Ollama) to generate responses
- ✅ **HTTP Communication**: Support for making API calls to local LLM endpoints
- ✅ **Prompt Processing**: Ability to send prompts and receive responses from LLMs

#### 2.2.2 Tool Usage Framework
- ✅ **Tool Interface**: IToolActor interface for implementing tool functionality
- ✅ **Tool Request/Response**: Standardized ToolRequest and ToolResult structures
- ✅ **Tool Chaining**: Support for sequential execution of tools and forwarding data between steps

#### 2.2.3 Human Interaction
- ✅ **HumanAgentAdapter**: Special agent type that allows human input via CLI
- ✅ **Fallback Mechanism**: Ability for agents to delegate tasks to humans when they can't handle them
- ✅ **CLI Interaction**: Support for receiving multiline input from users via terminal

#### 2.2.4 CLI Interface
- ✅ **Command-line Utility**: Simple CLI for submitting prompts to the Agctor system
- ✅ **Runtime Selection**: Ability to specify which actor runtime to use
- ✅ **Status Monitoring**: Display of processing status and results in the console
- ✅ **Timeout Handling**: Support for maximum wait times on agent processing (5 minutes default)

### 2.3 Development Tools
- ✅ **Dependency Injection**: Integration with Microsoft.Extensions.DependencyInjection
- ✅ **Logging**: Comprehensive logging with support for multiple severity levels and structured output
- ✅ **Error Handling**: Robust error handling with context preservation and standardized responses
- ✅ **Unit Testing**: Extensive test coverage for interfaces and components

#### 2.3.1 Code Execution
- ✅ **Multi-language Support**: Extensible architecture for executing code in different programming languages
- ✅ **C# Execution**: Dynamic compilation and execution of C# code using Roslyn
- ✅ **Python Execution**: Dynamic execution of Python code using IronPython
- ✅ **Language Detection**: Automatic language detection from file extensions
- ✅ **Alias Support**: Recognition of language aliases (e.g., "c#", "py", "python3")
- ✅ **Extensibility**: Pluggable architecture for adding new language executors

## 4. Limitations and Constraints

### 4.1 Runtime Support
- ✅ **InMemory Runtime**: Fully functional
- ⚠️ **Orleans Adapter**: Placeholder only, not yet implemented
- ⚠️ **Proto.Actor Adapter**: Placeholder only, not yet implemented

### 4.2 Performance Considerations
- Current implementation focuses on correctness rather than optimization
- Message processing is single-threaded within an actor
- No persistent state management implemented yet

### 4.3 Tool Ecosystem
- Limited number of tool implementations currently available
- Tool chaining mechanism is new and requires further testing with complex scenarios
- No standardized method for tool discovery or capabilities declaration

### 4.4 Language Support in CodeExecutorTool
- Currently supports C# and Python execution
- C# execution relies on Roslyn for dynamic compilation
- Python execution requires IronPython package
- Additional languages can be added through the extensible executor architecture

### 4.5 Agent Tracking and Monitoring
- Limited chronological tracking of agent operations
- No visualization layer for agent interaction flows
- Basic monitoring through console logs only

## 8. Conclusion

The Agctor System continues to evolve as a robust foundation for building agentic applications using the actor model. The recent refinements to agent lifecycle management, hierarchical coordination through root agents, and enhanced error handling significantly improve the system's reliability and operational clarity.

With its pluggable architecture, MCP-compliant messaging, tool framework, and now enhanced agent coordination capabilities, the system enables the development of flexible and extensible agent-based systems that are easier to maintain and troubleshoot.

While some advanced features like comprehensive activity tracking and runtime adapters are still in development, the current capabilities allow for effective local development, testing, and prototyping of agent workflows with LLM integration, code execution in multiple languages, human-in-the-loop processes, and robust error handling.
